## 1. 产品概述

### 1.1 产品定义

personal_blog 是一款面向个人创作者的轻量级博客网站系统，支持图文混排的文章发布、图片与视频展示、文章分类与搜索，以及基础的读者互动功能。目标是让个人用户在无需复杂技术配置的前提下，拥有一个美观、快速、易维护的个人内容发布平台。

### 1.2 目标用户

| 用户角色 | 描述 |
|----------|------|
| **博客作者** | 使用平台发布和管理内容的个人用户，具备写作、摄影、视频创作等兴趣 |
| **读者/访客** | 浏览文章、查看多媒体内容、参与评论互动的访客 |

### 1.3 解决的问题

- **个人内容展示渠道缺失**：个人创作者缺乏一个集中展示文字、图片、视频的平台
- **技术门槛高**：现有方案（如自建 WordPress、GitHub Pages + 静态生成器）需要较高的技术投入
- **多媒体支持不足**：部分轻量博客方案对视频和图片的支持较弱，影响内容表达
- **读者互动薄弱**：个人博客通常缺少评论等基础互动功能，难以形成社区感

### 1.4 产品边界

- ✅ **包含**：文章 CRUD、图片/视频上传与展示、分类与标签、搜索、评论、响应式设计、后台管理
- ❌ **不包含**：多作者协作、付费订阅/会员系统、社交媒体自动发布、SEO 自动优化、多语言切换（v1.0 不纳入）

## 3. 功能需求

### FR1：文章管理（CRUD）

**优先级：P0**

| 子功能 | 说明 |
|--------|------|
| 创建文章 | 支持标题、正文（富文本编辑器）、封面图、摘要、分类、标签 |
| 编辑文章 | 支持修改已有文章的所有字段，保留编辑历史（v1.0 仅保留最后版本） |
| 删除文章 | 软删除，可在后台管理页恢复 |
| 发布/草稿 | 支持保存草稿和正式发布两种状态 |
| 预览 | 发布前提供实时预览功能 |

**验收标准：**
- 编辑器支持加粗、斜体、标题层级、列表、链接、代码块等基础格式
- 每篇文章必须包含标题和正文，其他字段可选
- 删除的文章在回收站中保留 30 天

---

### FR2：图片上传与展示

**优先级：P0**

| 子功能 | 说明 |
|--------|------|
| 图片上传 | 支持拖拽上传和点击上传，单图最大 10MB |
| 图片格式 | 支持 JPG、PNG、GIF、WebP |
| 图片编辑 | 支持基本裁剪和尺寸调整（v1.0 仅前端调整显示尺寸） |
| 画廊展示 | 支持文章内多图排列，自适应网格布局 |
| 图片懒加载 | 页面中图片采用懒加载，提升首屏加载速度 |

**验收标准：**
- 上传后图片自动压缩到目标质量（原图保留，展示用副本）
- 画廊模式下图片支持点击放大查看

---

### FR3：视频上传与展示

**优先级：P0**

| 子功能 | 说明 |
|--------|------|
| 视频上传 | 支持拖拽上传和点击上传，单视频最大 100MB |
| 视频格式 | 支持 MP4（H.264/AAC）、WebM |
| 播放器 | 集成轻量 HTML5 视频播放器，支持播放/暂停/进度条/音量控制 |
| 缩略图 | 上传时自动提取第一帧作为封面缩略图 |
| 外部视频嵌入 | 支持嵌入 YouTube / Bilibili 等平台的视频链接 |

**验收标准：**
- 上传完成后视频可在文章内直接播放
- 外部链接嵌入方式无需上传到本地服务器

---

### FR4：用户认证与授权

**优先级：P0**

| 子功能 | 说明 |
|--------|------|
| 注册/登录 | 邮箱 + 密码注册登录（v1.0 单作者模式，仅管理员账号） |
| 密码重置 | 通过邮箱发送重置链接 |
| 会话管理 | JWT Token 或 Session 机制，Token 过期自动登出 |
| 权限控制 | 仅登录作者可访问后台管理，前台页面完全公开 |
| 记住登录 | 支持「记住我」功能，有效期 7 天 |

**验收标准：**
- 未登录用户访问后台管理页重定向到登录页
- 密码加密存储（bcrypt 或等价方案）

---

### FR5：文章列表与分类

**优先级：P0**

| 子功能 | 说明 |
|--------|------|
| 文章列表页 | 按发布时间倒序排列，每页显示 10 篇文章，支持分页 |
| 分类管理 | 作者可创建/编辑/删除分类，前端按分类筛选文章 |
| 标签系统 | 作者可为文章打标签，前端支持按标签筛选 |
| 归档视图 | 按年/月归档，展示每月的文章数量 |

**验收标准：**
- 文章列表页每条展示：标题、摘要/首段、封面缩略图、发布日期、分类标签
- 分类和标签数据在作者删除最后一篇文章时自动清理

---

### FR6：搜索功能

**优先级：P2**

| 子功能 | 说明 |
|--------|------|
| 全文搜索 | 对文章标题和正文进行关键词搜索 |
| 搜索页 | 独立搜索页面，实时显示搜索结果数量 |
| 高亮匹配 | 搜索结果中关键词高亮显示 |
| 空结果提示 | 无结果时显示友好提示和推荐分类 |

**验收标准：**
- 搜索响应时间 < 500ms（数据量 ≤ 1000 篇时）
- 支持中文分词搜索（至少支持按词匹配）

---

### FR7：设置与个性化

**优先级：P2**

| 子功能 | 说明 |
|--------|------|
| 基本信息 | 博客名称、副标题/Slogan、作者名、头像 |
| 主题设置 | 提供至少 3 套预置主题（浅色/深色/自定义） |
| 导航栏配置 | 可自定义导航菜单项（首页、归档、关于等） |
| 社交媒体 | 可填写社交账号链接，在页脚展示图标 |
| 评论设置 | 开启/关闭评论功能，设置评论审核开关 |

**验收标准：**
- 主题切换后页面无刷新即时生效（或刷新后保持）
- 社交媒体链接至少支持：Twitter/X、GitHub、微信、微博

## 4. 非功能需求

### 4.1 性能

| 指标 | 要求 |
|------|------|
| 首页加载时间 | ≤ 2 秒（3G/4G 网络环境下） |
| 文章页加载时间 | ≤ 3 秒 |
| 图片懒加载 | 首屏外图片不阻塞页面渲染 |
| 视频流式加载 | 视频支持渐进式加载，首帧 < 3 秒 |
| API 响应时间 | 后端 API 平均响应 < 200ms |

### 4.2 安全

| 要求 | 说明 |
|------|------|
| HTTPS | 全站强制 HTTPS |
| 输入验证 | 所有用户输入进行服务端校验，防止 XSS 注入 |
| CSRF 防护 | 表单提交使用 CSRF Token |
| 文件上传安全 | 限制文件类型和大小，文件名随机化存储 |
| SQL 注入防护 | 使用 ORM 或参数化查询 |
| 敏感数据加密 | 密码使用 bcrypt 等强哈希算法，密钥使用环境变量管理 |

### 4.3 可用性

| 要求 | 说明 |
|------|------|
| 响应式设计 | 适配桌面端（≥1200px）、平板（768-1199px）、手机（<768px） |
| 无障碍基础 | 主要交互元素有合适的 ARIA 标签，图片有 alt 文本 |
| 错误提示 | 用户操作失败时给出明确、可理解的错误提示 |
| 空状态 | 各页面在无数据时展示友好的空状态引导 |

### 4.4 兼容性

| 平台 | 要求 |
|------|------|
| 浏览器 | Chrome（最新 2 版）、Firefox（最新 2 版）、Safari（最新 2 版）、Edge（最新 2 版） |
| 移动端 | iOS Safari 和 Android Chrome 完全兼容 |
| 视口 | 最小支持宽度 320px |

### 4.5 可维护性

| 要求 | 说明 |
|------|------|
| 代码结构 | 前后端分离，模块化设计 |
| API 规范 | RESTful API，统一错误响应格式 |
| 日志 | 服务端记录关键操作日志（登录、发布、删除） |
| 配置管理 | 环境变量配置文件，不同环境独立配置 |

## 5. 竞争分析

| 平台 | 优势 | 劣势 | personal_blog 差异化方向 |
|------|------|------|--------------------------|
| **WordPress** | 插件生态丰富，主题多样，SEO 支持好，全球用户基数最大 | 对初学者技术门槛高，自行维护服务器/插件更新繁琐，性能较重 | 更轻量、开箱即用、无需运维，专注个人博客核心场景 |
| **Notion** | 写作体验好，块级编辑灵活，数据库功能强大，多平台同步 | 非独立博客（域名受限），SEO 支持差，社区功能弱，商业化倾向 | 提供独立域名和完整的博客站点体验，更好的 SEO 和多媒体展示 |
| **GitHub Pages** | 免费托管，技术感强，适合开发者群体，Git 版本管理 | 必须使用 Markdown/静态生成器，无原生后台管理，视频/多媒体支持弱 | 提供可视化后台编辑器，支持视频上传，无需 Git 知识 |

**结论：** 个人博客市场已有成熟方案，但 personal_blog 以「零运维 + 多媒体友好 + 轻量美观」为核心差异化定位，面向非技术背景的个人创作者。

## 6. 成功指标

| 指标编号 | KPI | 目标值 | 衡量方式 |
|----------|-----|--------|----------|
| KPI-1 | **活跃读者数** | 上线 3 个月内月活跃读者 ≥ 100 | 通过服务端统计独立访客（UV） |
| KPI-2 | **文章发布频率** | 作者平均每 7 天发布 ≥ 1 篇文章 | 统计后台发布记录 |
| KPI-3 | **页面加载性能** | 首页 LCP < 2.5s，文章页 LCP < 3s | 使用 Lighthouse / Web Vitals 监控 |
| KPI-4 | **用户满意度** | 核心流程（浏览、发布）无重大阻碍反馈 | 上线后收集用户反馈，目标零 P0 级问题 |
| KPI-5 | **内容多媒体比例** | ≥ 60% 的文章包含图片或视频 | 统计文章多媒体字段填充率 |

## 7. 技术架构建议（供开发参考）

> 以下为推荐技术栈，非强制要求，开发团队可根据实际情况调整。

| 层级 | 推荐方案 |
|------|----------|
| 前端 | React + TypeScript + Vite + Tailwind CSS |
| 后端 | Node.js + Express / Fastify 或 Python + FastAPI |
| 数据库 | PostgreSQL 或 SQLite（v1.0 轻量场景可选） |
| 文件存储 | 本地存储（v1.0）/ 对象存储 OSS（后续扩展） |
| 部署 | Docker + Nginx 反向代理 + HTTPS（Let's Encrypt） |
